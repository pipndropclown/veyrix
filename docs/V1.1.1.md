# Veyrix 1.1.1 — Accounts, Cloud Sync & Themes

V1.1.1 adds optional Supabase authentication and user-scoped cloud persistence while preserving a fully functional Guest Mode. The paper account remains $10,000 virtual USDC; connected wallets are read-only identity displays and never fund it.

## Configuration

Set `NEXT_PUBLIC_SUPABASE_URL` and `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` (see `.env.example`). Run `supabase/migrations/20260906_v1111_accounts.sql`, configure the Supabase Auth site URL and `/auth/callback` redirect, then add the same public variables to Vercel. If variables are absent, auth is unavailable and local Guest Mode continues normally.

## Data and safety

Tables are `profiles`, `paper_accounts`, `paper_trades`, `automation_preferences`, and `user_preferences`, each protected by user-scoped RLS. Server routes derive `user_id` from the session. Research artifacts remain in the existing research store. Authentication hydration is persistence only and cannot evaluate strategies or execute trades. A browser must remain open for autonomous paper trading; cloud preferences do not create a background daemon.

Guest data stays under the existing local keys. Migration should offer save-device, use-cloud, replace-cloud (confirmed), or start-fresh; no automatic portfolio merge is performed. Sync failures leave local paper trading usable.

## Themes

Dark is the default; Light and System are available from the header and persist locally (`veyrix.theme.v1`). Theme changes do not alter candles, chart timeframe, automation, portfolio, or history. Wallet identity remains separate from Veyrix authentication and paper funds.

## Known limitations

Supabase is optional and must be configured by the deployment owner. Guest state is device scoped; conflict handling is conservative and no real-time trading, wallet signing, deposits, withdrawals, or real-money execution exists.
