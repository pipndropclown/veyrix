# Veyrix V1.4 — Multi-Agent Automation & Performance Analytics

V1.4 replaces V1.3's single active automation configuration with a browser-side multi-agent paper simulator. It supports BTC, ETH, and SOL Spot Paper and simulated Futures Paper, using one local virtual-USDC account. Nothing in the account represents exchange funds.

## Agents and scheduling

Each saved agent has an ID, short name, market, paper mode, strategy, candle timeframe, sizing preference, stop and target percentages, simulated futures leverage, enabled state, creation time, last signal/evaluation/action, processed candle identities, recent events, and a reference-based link to paper trades. Up to **six agents can be active** and up to 30 configurations are retained locally. Agents start paused when created. The account controller uses a local-storage lease so only one tab in the same browser profile evaluates and mutates that paper account at a time.

One scheduler batches enabled agents by `marketId:timeframe`. Candle datasets are shared from an in-flight/cache layer; agent identities still include agent ID, market, mode, strategy, timeframe, and candle timestamp, so processing a candle for one agent cannot suppress another agent. The dashboard chart can share the same market/timeframe response. Quotes are also briefly cached by market. The scheduler executes sequentially in creation order against the balance and positions resulting from earlier agents in that batch.

Only the newest available closed candle is evaluated. After the browser has been closed, agents do not replay a backlog of missed candles. Processed IDs and enabled/paused state are persisted, so an already handled candle is not replayed after reload.

## Position and capital rules

All agents and manual controls use the shared virtual USDC balance. A Spot allocation is a sizing preference; Futures allocation reserves simulated margin. Before entry, the requested size is compared with current available virtual USDC. An insufficient balance skips the entry without allowing the balance to go below zero. There is at most one open position per market and mode. An agent or manual position in BTC Spot blocks another BTC Spot entry, while ETH and BTC Futures may proceed if funds remain.

Autonomous trades retain `agentId`, `agentName`, and `source: AUTONOMOUS` through history. Manual trades are `source: MANUAL`. An opposite Futures signal closes an existing position first; that candle never opens a reversal. Pausing stops that agent's strategy entries and exits. Stop loss, take profit, and simulated liquidation checks continue for all open positions. Deleting an agent with an open position requires confirmation to detach it and leave it open under manual control; it is not automatically closed.

## Analytics

Agent performance is derived from recorded simulated trades. It includes total and completed trades, wins, losses, win rate, gross profit/loss, realized and unrealized P&L, averages and extremes, profit factor, expectancy, realized-equity maximum drawdown, current win/loss streak, and average holding time. Gross loss is shown as a positive loss magnitude. Allocated-capital return uses the cumulative capital allocated to completed positions, so it is a turnover-based historical measure. Futures return on margin uses realized Futures P&L over completed Futures margin. These are not annualized.

The individual equity curve is cumulative **realized P&L**, ordered by trade exit time, starting from zero; combined agent equity curves are intentionally not drawn. The comparison table displays the underlying trade, win rate, P&L, drawdown, profit factor, and expectancy figures next to the score. Aggregate figures sum recorded agent trades and current agent positions only.

### Veyrix Agent Score

The score is withheld until the agent has at least five completed trades. When sufficient, it rounds this weighted sum to an integer in `[0,100]`; each component is first clamped to `[0,100]`:

* **Return (25%)**: `50 + 500 × net realized P&L / cumulative allocated capital`.
* **Drawdown (25%)**: `100 − 100 × maximum drawdown / average capital per completed trade`.
* **Profit factor (20%)**: `50 × gross profit / gross loss`; if there is no gross loss, this is 100 only when gross profit is positive, otherwise 0.
* **Expectancy (20%)**: `50 + 1000 × expectancy / average capital per completed trade`.
* **Trade sufficiency (10%)**: `100 × completed trades / 20`.

This transparent descriptive score is not investment advice and does not predict future performance. A higher historical score does not establish profitability.

## Persistence and V1.3 migration

Guest Mode keeps the versioned `veyrix.agents.v1` configuration alongside the existing paper-account snapshot to avoid copying full trade records. Trades remain in the existing account history and carry ownership references. A V1.3 single automation setting is migrated automatically into one agent, including market, mode, strategy, timeframe, allocation, risk levels, leverage, enabled state, and processed candle IDs. Matching autonomous history is linked to the migrated agent; migration is guarded by a persisted one-time flag. If saved agent data fails schema validation, the interface reports the issue and preserves the original local data rather than overwriting it.

## Research linking

An agent can open Research Workspace with its market and strategy preselected. Its automation candle timeframe is shown as context; the user chooses a historical research period and explicitly starts the run. Opening the link never starts a research job by itself.

## Safety and limitations

Veyrix remains PAPER TRADING ONLY. Agents execute in the browser against public market/candle reads and a locally stored virtual account. There are no exchange accounts, private credentials, wallet signing, real orders, real borrowing, deposits, withdrawals, or transaction submission. Simulated leverage only changes paper exposure and margin accounting. Agents stop evaluating when the controlling browser tab is closed. Browser storage is not a cloud backup, and a browser-profile lease cannot coordinate different devices. Candle/provider gaps, quote caching, modeled execution, limited market support, and local persistence remain constraints. Research and score metrics describe historical simulations and make no return prediction.
